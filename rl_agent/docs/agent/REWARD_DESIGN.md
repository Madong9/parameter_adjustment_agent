# 奖励设计与编译

`EnvironmentInspector` 会解析实际 `_reward_*` 方法和奖励尺度配置类。对于 Go2，会合并基础配置和 Go2 覆盖值。注册表条目包含实现符号、配置键、默认权重与符号、预期原始范围、依赖变量和支持阶段。

Provider 的第一次回复同时包含一个 `TaskSpec` 和三个 `RewardPlan` 候选。编译器会拒绝缺失奖励、非对象参数、非有限或过大的权重，以及不安全的惩罚符号变化。通过校验后，会在候选目录中生成新的 `config.yaml`、`config.diff`、配置哈希、父版本与版本元数据、奖励计划、提示词和回复；原始配置不会被修改。

真实训练包装器导入 Unitree 的实际任务注册表，在内存中应用编译后的奖励尺度，并调用真实 `OnPolicyRunner`。基础环境的奖励插桩会通过现有 `Episode/*` TensorBoard 日志记录原始均值/标准差/最小值/最大值、配置权重、加权均值/标准差、贡献比例、非零比例、饱和比例、全阶段数值和原始 episode 累计值。

新生成的奖励代码属于可选扩展并保持隔离。`RewardCodeValidator` 禁止导入、文件/网络/进程/系统名称、双下划线属性和非白名单调用或张量；只有通过 batch 形状及有限值测试后才能保存文件。

候选选择首先检查安全，再比较成功率、物理任务指标、多种子证据、视觉一致性、PPO 稳定性、能耗和奖励投机迹象。总奖励绝不能单独作为完成依据。
