# 登录误报与系统边界加固

这些修复不改变 PPO 算法，不降低动作验收阈值，也不把环境健康或 Mock 结果视为动作成功。已有 checkpoint 不会被自动删除、重新认证或重新训练。

## 为什么没有退出登录，却显示登录过期

旧实现扫描 OpenCLI 返回的整页文字：出现“登录”“注册”且没有英文 `message chatgpt` 就判断登录过期。中文“奖励注册表”以及新版输入框名称就能误触发这个条件。

现在使用 `providers/chatgpt_dom.py` 的结构化控件探针：

- 排除用户消息、助手消息和输入框正文；正文中讨论注册、验证码、额度错误不构成站点状态证据。
- 只在真实可见登录控件、身份验证表单或登录对话框出现时请求人工处理；正常账号菜单不与注册文字混淆。
- 验证码只检查可见验证控件；不会自动处理或绕过验证码。
- 用量只从站点提示控件读取，不根据助手引用的历史错误推断额度耗尽。
- 地址仍必须属于配置的目标站点。探针未知不能被表述为“账号已过期”，后续填写仍要求真实输入框及全文确认。

备用豆包采用独立的可见控件探针，同样排除历史消息和隐藏验证节点；健康检查必须发现实际输入框，不能仅凭“新对话”文字宣称服务可用。

结构化 JSON 补读也核对当前用户消息 ID、助手归属、助手身份变化和生成完成状态。另一任务即使返回相同 Schema 的合法 JSON，也不能替代当前回复。

## 上位机接口和资源生命周期

上位机只允许本机 loopback 监听。打开合法本机首页后自动建立每次启动独立的会话 Cookie；用户不需要填写新的 API 密钥。API 校验会话、Host 和 Origin，变更请求必须为 JSON。停止和恢复也发送 JSON 空对象。未知来源、伪造 Host、未初始化会话与非 JSON 操作被拒绝。

这个机制用于保护本地界面的请求来源，不是多用户账号系统。不要通过未受控代理向外公开端口；远程访问需要受控隧道以及额外的身份与 TLS 边界。会话令牌不写入代码、配置、URL 或访问日志。

训练、策略播放和可行性 Viewer 共享启动预留与 GPU 资源边界。检查、预留和登记在同一临界区完成，启动失败释放预留，不能由并发请求覆盖进程引用。

停止流程覆盖外层 CLI 和真实训练子会话：

- CLI 收到终止信号或退出时回收自身登记的训练组。
- 作业控制记录包含签名和进程启动身份；上位机在外层异常退出后也能验证并回收已登记子组，不仅杀外层 CLI。
- 回收不能把组长退出当作所有后代已经消失；残留后代也必须处理。
- 桌面退出先进入 shutdown 状态、禁止派发，取消全部排队任务，再清理运行任务和 Viewer。

## 训练恢复与验收

每次运行冻结评估种子和采样要求。恢复不能因为某些 checkpoint 丢失而悄悄从三种子变成单种子。配置、运行身份、checkpoint 来源和缓存覆盖必须一致；旧记录只有具备足够的持久化证据才能兼容恢复。

新 checkpoint 清单保存内容 SHA256。历史任务没有保存这个摘要时，兼容恢复只能核对既有种子、配置、manifest 和环境指纹，不能追溯证明 checkpoint 从未被改写，也不会伪造历史摘要保证。

训练操作有稳定幂等身份，启动前持久化预算和阶段记录。训练失败允许合法收束到人工复核；中断恢复检查阶段证据，不能重复扣减同一操作，也不能把未完成的新训练当作完整评估。

对确实适用且启用的反事实测试，文件缺失、样本不完整或数值非有限不能默认通过。固定侧翻等不适用任务仍不要求停车反事实测试，避免把任务外能力强加为验收标准。

## 自定义奖励代码

默认生产流程仍使用注册奖励和结构化计划。可选的生成代码扩展严格拒绝间接调用、未知调用和非纯函数顶层代码；张量冒烟验证改为资源受限的独立 CPU 进程，采用最小环境，不继承宿主 API 凭据。

受限进程和 AST 校验不是任意 Python 的通用安全沙箱。不要移除白名单后执行不可信代码；扩大代码能力时需要额外的操作系统级文件、网络和系统调用隔离。

## 记忆与文件边界

- 重复支持证据不能重新激活 `superseded` 规则；反证和替代关系保持有效，重新激活需要明确治理过程。
- 新长期记忆保存经过重新核验的小型不可变证据快照和文件摘要。重复训练同一动作不能覆盖旧经验的真值来源。
- 检索复核快照摘要和验证结果。缺少可信快照的旧记录保留，但不自动进入生产上下文；不能给旧记录补写虚假的成功证据。
- 程序记忆身份覆盖版本、流程策略和提示词内容，而不只覆盖 Schema；同 ID 不允许覆盖不同程序内容。
- 单任务清理以该任务为边界；迁移以允许根目录为边界。文件或父目录符号链接被拒绝，不跟随链接删改其他任务或外部文件。
- 超时诊断默认只保留白名单状态、正文长度及消息身份摘要；不再自动保存整页 HTML、私人会话正文或带查询参数的资源 URL。

历史上生成的调试文件没有自动删除。请按实际保留需求自行检查和清理，避免丢失已有实验调查资料。

## 应用修复后继续已有任务

先停止并重新打开上位机，确保服务和训练子进程加载的是新代码。保持已登录 ChatGPT 的 Chrome 和 Browser Bridge 连接。对有完整 checkpoint 的人工复核作业，使用“从当前策略继续闭环”，不要直接重新下发同一动作覆盖任务级摘要。

也可以在 `rl_agent` 目录下执行：

```bash
conda activate rl_agent
python -m rl_training_agent resume --task-id task-fe2231742e
```

这个命令会调用模型并继续使用剩余训练预算，不是只读检查。本次修复不会自动执行它。策略是否成功仍由重新评估的真实证据决定。

## 验证范围

回归测试覆盖独立 Chrome 的本地 DOM、模拟 Provider、真实短时普通进程树、临时 HTTP 服务和合成实验/记忆证据。没有使用个人 Chrome 配置启动测试，没有发送真实模型消息，没有执行 PPO 长训练。

测试默认禁止隐式读取工作区 `.env`；只有显式的临时配置夹具允许测试环境变量解析。旧版本凭据文件不修改、不上传。

已有 `task-fe2231742e` 只读恢复前置检查通过，保留三个种子 checkpoint 和剩余 1050 次迭代预算。当前个人 Chrome 的 OpenCLI 只读探针超时，因此这些测试不构成真实 ChatGPT 会话端到端验证，也不表示动作已经完成验收。
