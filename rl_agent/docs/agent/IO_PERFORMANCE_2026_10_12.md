# 训练监控与视觉附件性能优化

日期：2026-10-12。本轮保留工作区已有修改，在其上完成增量优化。

## 已完成

| 位置 | 原有问题 | 当前行为 |
| --- | --- | --- |
| `training/early_stopping.py` | 每次先读取整个日志，再截取最后十万字符；不完整的奖励数字可能抛出异常 | 最多读取末尾 400,000 字节，保留最后十万字符检查窗口；支持科学计数法并忽略不完整数字；文件消失返回 `missing_log` |
| `metrics/ppo_collector.py` | 最新值和迭代号分别扫描 TensorBoard，重复读盘且可能来自不同时间的结果 | 从同一次扫描结果汇总最新值和最大迭代号，保留空标签、未知标签和缺失指标的原有处理 |
| `visual/frame_sampler.py` | 每帧都重新定位；异常时未保证释放解码器；定位失败仍可能把当前帧标成目标帧 | 连续帧顺序读取，仅跳帧时定位；定位失败忽略该帧；用 `finally` 释放句柄 |
| `visual/contact_sheet.py` | 先分配完整大画布，绘制后才缩小，`max_dimension` 无法限制中间画布内存 | 在分配之前计算缩放后的格子尺寸；验证尺寸和列数；画布最长边不超过上限，各帧继续保留 |
| `visual/evaluation_pipeline.py` | 同一相机为各附件反复打开、解码重叠帧 | 每个相机合并全部请求并只解码一次，接触图和起跳/落地事件图共享帧结果 |

本轮没有改动训练预算、奖励合同或验收阈值。接触图缩小时采用先缩放格子再绘制标注的方式，布局像素和文字大小可能与旧图略有不同；帧选择和同步物理证据保持原逻辑。

## 本机性能测量

使用 Python 3.8.20、NumPy 1.24.4、OpenCV 4.13.0.92；与提交 `33f1f09e663e75f7d3cf876fc6860fa9e1a26500` 中对应模块比较。这五个模块在本轮开始前没有工作区修改。全部输入、视频和图片位于临时目录，测量后清理。

每项执行三次，耗时取中位数。内存通过 `tracemalloc` 记录测量操作期间的最大增量分配，不包括提前构造的输入帧，也不代表整个进程 RSS。

| 场景 | 原耗时 | 当前耗时 | 原增量内存峰值 | 当前增量内存峰值 |
| --- | ---: | ---: | ---: | ---: |
| 64 MiB 稀疏日志，尾部有正常奖励行 | 54.238 ms | 4.400 ms | 128.007 MiB | 0.768 MiB |
| 128 帧、320×240 格子、4 列、最长边上限 2048 的 PNG 接触图 | 34.406 ms | 24.942 ms | 30.344 MiB | 2.026 MiB |
| 离线生成的侧视 MP4，30 FPS，顺序解码全部 150 帧 | 211.357 ms | 61.256 ms | 131.867 MiB | 131.859 MiB |

150 帧逐帧比较索引与 NumPy 像素内容，全部一致。解码仍返回全部图像，因此其结果内存没有显著下降；加速来自减少重复定位。短视频、磁盘缓存、编码方式和硬件会影响耗时，以上比例不能直接当作整个训练的加速比例。

## 后续优化重点

1. **真实多种子基准**：已有 `config/benchmarks.yaml` 协议，但最新实现状态文档仍缺完整长训练收敛证据。应记录成功率、稳定性、接触违规、训练用时和不同种子的差异，才能判断奖励与参数优化是否改善真实动作。此项需要 GPU 训练和浏览器 Provider 的有效会话。
2. **复杂动作的专用实现**：贴地侧滚仍缺经过验证的计划机体接触合同和专用执行器，应先补接触阶段与独立物理验证，再谈学习效果；不能用空翻合同替代侧滚。当前边界详见 `OPTIMIZATION_2026_10.md`。
3. **编排与界面模块拆分**：`orchestration/orchestrator.py` 为 2841 行，`web_ui.py` 为 1506 行。可逐步将恢复校验、候选训练、评估与附件生成提取为独立服务，并沿用现有回归保护状态、预算和证据语义。大范围重构应单独开展，便于审查已有未提交修改。
4. **长期检索的计算复用**：`rag/knowledge_base.py` 每次检索重新对所有候选片段分词，并分别为 BM25 和 TF-IDF 构建词频。历史实验增加后，可缓存分词与词频；排除当前任务时仍须正确更新语料统计，并测试索引刷新和排序一致性。
