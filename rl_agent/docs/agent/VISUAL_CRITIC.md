# 视觉评论与同步 rollout

真实录制器使用仿真摄像机生成正面、侧面和总览 MP4，并把同一策略步骤写入 `trajectory.parquet` 和 `rewards.parquet`。三台摄像机按照机器人 base 位置和 yaw 跟随，使用较近距离和 55 度视场角，避免机器人移动后离开画面。若请求 FPS 不能被策略控制周期整除，视频使用实际采样 FPS 编码，元数据同时记录请求值和实际值，避免加速播放。

事件完全从轨迹列推导，包括运动开始、滚转/俯仰/角速度极值、碰撞与摔倒、下蹲/起跳/最高点/落地/恢复、各足触地、滑动和 episode 结束。总览图使用均匀帧，侧面图补充事件前后连续窗口，多视角图在同一批帧上并列正面、侧面和总览画面。标注只包含 command、实际速度、姿态、足端接触/接触力、全部非足刚体碰撞力、摔倒和滑动，不显示奖励或 PPO 数值。

`behavior_evidence.json` 对全部轨迹帧执行同步扫描，而不是只检查抽样图片。它记录 command 向量顺序与目标大小、机体坐标实际速度和跟踪误差、最长连续后腿站立区间、腾空区间、足端接触比例、关键事件窗口，以及除四只脚之外所有刚体的最大接触力。Go2 的默认 thigh/calf 惩罚列表和 base 终止列表只作为附加诊断，不能替代全非足刚体扫描。

第一阶段发送任务语义、视觉材料和不含奖励的同步物理证据，返回 `VisualBehaviorReport`，其中阶段分数只能是 0、0.5 或 1。`evidence_findings` 必须分别回答 command 跟踪、身体碰撞、连续站立、垂直运动和足端接触；完整轨迹已经回答的问题不能再以“静态图片无法判断”列入不确定项。第二阶段才融合奖励统计、PPO 统计、实验谱系和剩余预算。视觉证据不能覆盖安全约束或数值验收门槛；视觉与数值冲突时必须进入人工审核。

精确接触时序、足端滑动、扭矩和能耗始终来自轨迹数据，不能依赖视觉猜测。

已有 rollout 可使用 `python -m rl_training_agent visual-audit --task-id TASK_ID --rollout final/evaluation_rollout --provider opencli` 单独复评，无需重新训练。
