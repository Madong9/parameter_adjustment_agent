# 桌面上位机软件

## 概述

桌面上位机是项目的主要本地操作入口。它由本机训练服务和 Chrome/Chromium 的独立应用窗口组成：窗口没有地址栏、标签栏、书签栏或普通浏览器导航，只显示训练操作台，因此使用体验与桌面软件一致。它不需要安装 Qt、Electron 或额外 Python GUI 依赖。

应用窗口使用一次性的隔离浏览器配置，不读取个人 Chrome 历史、Cookie 或扩展。训练状态和日志只通过随机分配的 `127.0.0.1` 本机端口传输，不暴露到局域网。

桌面程序包含：

- 自然语言动作任务编辑器；
- Go2、G1、H1、H1-2 训练机型选择；
- 离线演练和真实 GPU 仿真训练选择；
- 当前实验编号、状态、阶段和圆形进度仪表；
- 自动闭环轮次、奖励版本、诊断决策和剩余训练预算；
- 分阶段完成轨迹；
- 实时训练日志、复制、清屏和自动跟随；
- 最近实验列表；
- 受控训练进程组的安全停止。

真实训练期间，状态区会显示当前候选或随机种子、`当前迭代/目标迭代`，圆形进度会在冒烟训练、候选筛选和完整训练各阶段内部连续推进。评估未通过后，状态会显示“闭环第 N 轮、奖励 vN、当前决策”，然后回到修订和续训阶段；只有视觉、任务指标和硬约束联合通过才显示“训练完成”。完整高频输出保存在候选目录的 `stdout.log`，上位机日志只接收约每 1% 一条的进度摘要和子进程错误，避免长训练产生数十 MB 界面文本。

桌面端和浏览器备用入口共用同一套 `JobManager`，因此训练参数白名单、单作业互斥、日志格式和停止策略保持一致。两种界面均不具备实体机器人控制或部署能力。

## 启动方式

在文件管理器中双击项目目录内的 `启动上位机.sh`，并在系统询问时选择“运行”。

如果终端已经位于 `rl_agent` 目录，直接执行：

```bash
conda activate rl_agent
python -m rl_training_agent desktop
```

如果终端位于上一级 `parameter_adjustment_agent` 目录，执行：

```bash
conda activate rl_agent
cd rl_agent
python -m rl_training_agent desktop
```

不要在已经位于 `rl_agent` 目录时再次执行 `cd rl_agent`，否则 Bash 会尝试进入不存在的 `rl_agent/rl_agent` 并报告“没有那个文件或目录”。

启动脚本不包含主机绝对路径。它先根据脚本自身位置进入 Agent 目录，再使用已经安装的 `rl_agent` Conda 环境启动软件，因此整个项目目录移动或上传后仍可使用。

## 操作流程

1. 在“动作任务下发”中描述动作、地形、速度、稳定性和禁止行为。
2. 选择与训练配置对应的机器人机型。
3. 首次运行选择“离线演练”；确认流程正常后再选择“真实训练”。
4. 点击“下发训练任务”，或按 `Ctrl + Enter`。
5. 在右侧观察进度与阶段，在下方查看训练日志和最近实验。
6. 需要中止时点击“安全停止训练”。

同一时刻只允许一个界面作业运行，以免多个训练争抢 GPU。关闭软件窗口时，本地服务会一并关闭；如果本次窗口启动的训练仍在运行，启动器会安全停止对应训练进程组并保留已经产生的实验文件。

## 数据位置

桌面端不创建主机专属路径，运行数据仍使用项目配置中的相对目录：

```text
artifacts/ui_jobs/<job_id>/job.json
artifacts/ui_jobs/<job_id>/training.log
experiments/<task_id>/
```

离线演练固定使用 Mock Provider。真实训练固定使用 OpenCLI Provider，并复用现有 Unitree GPU 仿真训练流程。

## 图形环境与兼容模式

主桌面入口按顺序查找 `google-chrome`、`chromium` 和 `chromium-browser`。当前机器已经安装 Google Chrome。若目标机器没有这些程序，入口会自动回退到 Tk 兼容界面。

如果终端提示无法连接图形桌面，说明当前会话没有可用显示服务器。请在 Ubuntu 桌面会话中启动，而不是在纯 SSH 终端中运行。远程环境可继续使用浏览器版：

```bash
python -m rl_training_agent ui --no-browser
```

只有需要明确测试旧版兼容界面时，才运行：

```bash
python -m rl_training_agent desktop-tk
```

Tk 兼容界面会自动修正异常 DPI 并选择 Tk 实际支持的中文字体，但旧式 X11 位图字体的观感仍可能因系统而异，因此不再作为默认入口。
