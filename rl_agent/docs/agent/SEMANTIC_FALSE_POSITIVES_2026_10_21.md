# 前空翻任务设计误判修复

2026-10-21，作业 `649740f72fb7`（`task-ccd8109bb2`）在奖励设计后进入人工复核，尚未启动 PPO。原始指令是“向前腾空翻跟头”。

## 原因

这次结构校验已经通过，阻塞来自两个本地误判：

- 任务说明写着“前空翻与绕机体纵向轴的侧空翻、允许机体接触地面的前滚翻具有不同的动作语义”。分类器将用于对照的侧空翻也当成肯定目标，同时报出两条侧向动作冲突。
- 必选 `pitch_axis_error` 已设置 `< 0.5`，单位是 `dimensionless`。前置校验只接受 `ratio`、`1` 和空字符串，确定性验收也缺少该别名，因此误报轴向合同无效。

进一步离线审查发现，前两个候选的接触终止条件“非足端刚体接触力超过现有安全策略的1.0 N阈值。”具有明确执行语义，但解析器只接受英文比较。第三个候选还将奖励参数写进了不支持动态更新的课程参数中；这是独立的真实配置错误。

## 修改

`utils/task_semantics.py` 对明确的动作比较句保留主语动作，仅移除对照项。修饰词限定为轴向、接触方式等已知词，不跨独立动作要求。逆向比较、比较后的侧翻要求、“两者都要执行”及肯定双动作继续受到冲突检查。

`utils/units.py` 统一无量纲别名，前置语义校验和最终确定性验收共同使用。支持 `dimensionless`、`unitless`、`无量纲` 等等价拼写及首尾空白、大小写；不改原始阈值或单位文本。百分比、弧度、力和速度单位不会当成直接可比的比例。轴向上界仍要求正确比较方向及 `0 <= value < 1`；单位不兼容时单独报告收到的单位。

`training/contact_semantics.py` 解析完整匹配的中文非足端接触力比较，保留原文、数值和严格/非严格方向。缺数字、缺 N 单位、否定、多条件、延时、接触豁免及其他部位的条件继续拒绝。解析结果与等价英文条件共用相同安全合同，不能提高固定或任务安全阈值。
