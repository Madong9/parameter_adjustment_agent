# GPT 奖励修复改为字段补丁

2026-10-22。奖励提案遇到可定位问题时，只请求有问题部分的修改，本地保留完整来源并合并补丁。

## 三条入口

1. **奖励 JSON 类型校验**：明确表示差异先用已有无损规范化处理。仍有类型错误时，OpenCLI 和百炼根据 Pydantic 的 `validation_errors` 生成精确 `add/replace` 路径，请求 `RewardSchemaFieldRepair`，而非重新输出整份奖励。补丁需匹配来源 SHA-256，已有字段继续经过保留检查。没有完整可解析 JSON 时保留原有有限语法恢复；不凭部分文本猜执行合同。
2. **初次奖励业务审查**：全部候选被拒绝且没有本地能力缺口时，请求 `repair_reward_plans`。只发送未通过候选的来源、哈希、问题和允许操作。已有合格候选可直接继续，其余候选隔离；不会为修复不合格候选重新生成整个 TaskRewardBundle。
3. **训练失败后新提案的审核**：首次仍按失败证据生成新提案。该提案的后续审核问题只走补丁，来源是最近一次提案，不退回已训练父计划，不丢失上轮已修好的内容。版本关系由本地维护。

## 修改范围

`rewards/repair_scope.py` 从固定任务、候选和注册表的确定性谓词生成权限，不解析中文错误文本猜位置。可定位的问题包括无效权重、关闭必要信号的课程覆盖、未实现参数、缺失目标或行为对应表、空说明或反例、无效奖励引用、候选验收漂移和净旋转目标不一致。

- 已有合法字段、有效候选、任务身份、版本、坐标系、风险说明及设计说明不开放修改。
- 缺少训练信号时，仅允许追加指定的已注册奖励；未注册奖励仅允许删除该不可执行条目。
- 候选验收字段只能精确恢复为固定 TaskSpec 的对应值，不能自行修改验收或安全阈值。
- 新增目标/行为链接限制指定身份；新增反例限制非空文本。列表允许精确字段修改、删除无效项或末尾追加，不允许整体替换、插入和排序。
- 无法定位、实现缺失、任务硬约束冲突和含糊安全条件不会获得扩大修改范围的权限。

`schemas/reward_repairs.py` 定义 `RewardRepairBundle`：每个候选补丁包含 `candidate_index`、`base_sha256`、`patches`；每条字段补丁包含 `op`、路径数组 `path` 及所需的 `value`。操作及路径必须匹配本地权限，精确值与新增身份约束也由本地检查。

`rewards/patches.py` 按候选原子合并，拒绝过期哈希、未请求候选、越权字段、重复候选及路径重叠。同轮删除数组元素时，其他字段的地址始终相对于原始快照：先修改与追加，再倒序删除，避免改错后面的奖励。一个候选的补丁被拒绝不会覆盖其他候选。合并后重新进行类型、注册表权重、业务、任务、安全与编译校验；不会再通过重跑规范化改动无关字段。

对仍忽略格式补丁要求、返回整份对象的旧奖励回复，只投影可定位且数组身份一致的错误字段；不能覆盖有效值，也不能借容器级错误清空整表。请求和原始回复仍保存。

## 次数、预算和记录

格式修复使用原 Provider 的重试上限，业务修复使用 `reward_design_review_retries`。无变化、格式错误、越权或过期补丁都会受现有次数限制，不调用整份设计作为修复回退。初次设计审核修复不消耗 PPO 训练修订额度；训练失败后的新版本仍受原有训练预算与修订次数约束。

审计产物：

- 初次业务修复：`reward_repairs/request_*.json`、`response_*.json`、`patch_audit_*.json`、`effective_plans_*.json`。
- 失败后提案修复：`reward_redesign/round_*/field_repairs/` 下相同记录。
- 格式补丁：Provider 会话目录中的 `schema_error_patches_*.json` 或百炼的 `*_schema_error_patches.json`；网页拒绝记录为 `schema_patch_rejection_*.json`。

只支持完整设计的旧 Provider 不会被静默当作局部修复接口使用。原生 OpenCLI、百炼、多角色路由和主备路由已接入新接口。
