# 通用动作奖励设计提示词 v6

初次结构化设计、兼容设计入口和失败后的完整重设计共用 `prompts/reward_design_common.md`。角色模板只描述本次输入、固定合同和输出 Schema，避免不同入口沿用不同的奖励配方。`agents/reward_prompt_policy.py` 从当前实现表注入指标对应关系、聚合特例、安全项、参数白名单和接触判定；版本为 `reward-design-v6`，编译请求保留完整内容和哈希。

设计顺序是：固定动作语义 → 核对实现能力 → 建立指标与行为对应表 → 区分进度/完成/维持/恢复 → 保持安全项有效 → 核对实际贡献与课程 → 检查错误动作反例 → 响应审核意见。动作应遵循自身接触、坐标系、连续性和结束条件，不把全部动作套成起跳—翻滚—落地。

| 情况 | 模型应如何处理 |
|---|---|
| 已注册安全奖励遗漏 | 补齐对应项及各课程负权重；torque_limits 对应力矩超限，torques 不能替代 |
| 有验收指标但无已登记训练信号 | 标记能力缺口，不能仅引用相似奖励名称 |
| 初始站立与落地后恢复混淆 | 根据聚合语义和真实门控区分 stable_support 与 landing_recovery |
| 峰值角速度大但净旋转小 | 作为错误动作反例；roll_rotation 不能覆盖缺失的净滚转实现 |
| 课程覆盖或门控未触发 | 核对有效权重、参数及状态条件；activation_condition 文本不会执行 |
| 历史建议缺少本轮证据 | 标明来源与局限，作为假设，不宣称已经执行或成功 |

能力缺口用现有 Schema 表达：`design_rationale` 中写 `[CAPABILITY_GAP]`、缺失目标/实现及补齐要求；该目标的 `objective_links.reward_terms` 留空，保留原验收指标。回复可被解析，但本地审查会拒绝准入。此次没有关闭审核、放宽阈值、增加预算或改变有限重试次数，提示词本身不会创建奖励函数，必须由本地代码实现并登记。

反例说明是设计与审核材料，不等同于已完成反例仿真。提示词和本地审核约束计划，不能保证任意动作都能学会。

本地能力已补齐 `net_roll_progress` 和可由显式计划启用的 `torque_limits`。净滚转进度按逐步展开 roll 计算，只在全足腾空时计分；正增益由历史最高进度限制，反向抵消扣分，达到 net_roll_target 后不再奖励多转圈，收益按控制 dt 归一化。目标角度必须为正且不得低于任务必选净角度阈值。该信号不替代单次动作、旋转轴、碰撞与落地恢复的独立验收。

通用动作中无法由当前注册表覆盖的指标写入 `reward_capability_gaps.json`，已有有限重设计流程会停止重复请求；失败重设计在本地能力缺失时保存报告并拒绝生成不可执行计划。配置遗漏仍由 GPT 在有限重试中修正，不放宽合同或预算。
