# 强化学习上位机界面

## 定位

上位机是自然语言训练 Agent 的本地操作面板，面向仿真训练任务下发和过程监控。它不是机器人实机遥控器，不会建立实体机器人连接，也不会调用部署程序。

界面提供以下能力：

- 输入希望训练的动作和约束；
- 选择 Go2、G1、H1 或 H1-2 训练配置；
- 选择离线演练或真实训练；
- 查看 Agent 当前阶段、总体进度和作业状态；
- 查看自动闭环轮次、奖励版本、诊断决策和剩余预算；
- 增量查看、复制或清屏显示运行日志；
- 对当前界面启动的训练执行安全停止；
- 在人工复核后从当前策略、checkpoint 和已采集 rollout 恢复自动闭环；
- 浏览实验目录中的最近训练记录；
- 查看动作约束、确定性规划、全身求解与真实物理验证的分层证据；
- 查看工作、情景、语义、程序四层记忆及当前实验的晋升结论；
- 对 Go2 直线行走任务从页面启动 Isaac Gym 可行性 Viewer。

## 启动

在 Agent 目录运行：

```bash
conda activate rl_agent
python -m rl_training_agent ui
```

默认地址为 `http://127.0.0.1:8765/`，启动后会尝试使用系统默认浏览器打开。可使用以下参数调整启动行为：

```bash
python -m rl_training_agent ui --no-browser
python -m rl_training_agent ui --host 127.0.0.1 --port 9000
```

建议保留默认的 `127.0.0.1`。将监听地址改为 `0.0.0.0` 会把操作台暴露给同一网络中的其他设备，使用前应配置主机防火墙和可信网络隔离。

## 运行模式

### 离线演练

离线演练固定使用 Mock Provider 和 `--dry-run`。它会走完任务设计、候选奖励、配置生成、模拟训练、rollout、视觉评估和最终报告流程，不需要 ChatGPT 登录或 GPU 长训练。首次使用界面时应先运行一次离线演练。

### 真实训练

真实训练默认使用多 Agent Provider：GPT/OpenCLI 理解动作并完成视觉评价，百炼 GLM 生成奖励和训练诊断，然后进入 Unitree GPU 仿真训练流程。使用前应完成以下检查：

```bash
python -m rl_training_agent doctor
python -m rl_training_agent opencli-test
```

还必须在启动上位机的同一终端设置 `DASHSCOPE_API_KEY`；使用百炼业务空间专属域名时，同时设置 `DASHSCOPE_BASE_URL`。密钥不会写入作业日志。

上位机不接受来自浏览器的任意命令、Provider 名称或文件路径。后端只根据经过白名单校验的机型和模式构造固定 CLI 参数数组，并以 `shell=False` 启动训练。

## 可行性与记忆面板

“动作可行性”面板读取当前作业的 `feasibility_report.json`，分别展示动作约束、确定性规划器、全身求解器和物理后端。`CAPABILITY_ONLY`、`INCONCLUSIVE`、`MOCK_VALIDATED` 不会被显示成真实物理通过；只有报告中的真实 Isaac Gym/MuJoCo 证据才显示静态或动态物理通过。对 Go2 直线前进/后退任务，可在训练作业结束后点击“在 Isaac Gym 中观察检验”。该窗口与策略播放共用 GPU Viewer 互斥锁，关闭窗口后按钮会自动恢复。

“四层记忆”面板每五秒读取统计数据，只返回数量和状态，不返回记忆正文。当前任务区显示工作记忆的状态、闭环轮次、奖励版本，以及是否通过证据门控晋升为情景记忆；全局区显示活跃/归档情景记忆、已生效/候选语义记忆和程序快照。未晋升不等于模块故障，通常表示实验尚未结束，或结果属于 dry-run、人工复核、Provider 故障、证据不足。

## 状态与日志

每个界面作业拥有服务端生成的 `job_id`，界面记录位于：

```text
artifacts/ui_jobs/<job_id>/
├── job.json
└── training.log
```

具体训练实验使用稳定的 `task_id`，仍写入 `experiments/<task_id>/`。界面从该目录的 `state.json` 读取训练阶段，并从 `loop_status.json` 读取当前闭环轮次、奖励版本、诊断决策及剩余资源，然后共同映射为进度仪表和中文阶段名。一次视觉或数值评估未通过时，进度会回到奖励修订/继续训练阶段并显示新的轮次，不会误报“训练完成”。刷新浏览器后，界面会从本地存储恢复最近查看的作业；日志采用字节偏移增量读取，不会重复下载完整文件。

只有状态为 `COMPLETED` 才表示视觉目标、任务物理指标和硬约束已经联合通过。`HUMAN_REVIEW` 表示 Provider 不可用、证据/需求存在真实歧义、安全修订无法执行或自动预算耗尽。界面会显示“等待人工复核”和摘要中的具体原因；只要已有可恢复候选，就会出现“从当前策略继续闭环”按钮。该操作复用既有奖励版本、checkpoint、闭环预算和当前轮次已经完成的 rollout，不重新执行任务设计、候选筛选和初始完整训练。

如果上位机服务在训练期间退出，历史界面作业会在下次启动时标记为“服务曾中断”。训练子进程可能仍在运行，因此不要仅凭该标记重复启动真实训练；应先检查对应实验状态和系统进程。正常操作时请优先使用页面内的“安全停止训练”。

## 安全边界

- 默认仅监听本机回环地址；
- 请求体限制为 64 KiB，动作描述限制为 2000 个字符；
- 机器人和运行模式均采用服务端白名单；
- 静态资源使用固定路由，不提供任意文件读取；
- 训练命令不经过 shell；
- 停止操作只作用于当前服务实例启动的受控进程组；
- 页面内容安全策略禁止外部脚本、外部连接和第三方资源；
- 实体机器人连接和部署不在上位机能力范围内。

## 常见问题

页面无法打开时，先确认终端仍显示“强化学习训练界面已启动”，再检查端口是否被占用。可通过 `--port` 选择其他端口。

训练工程显示“未就绪”时，检查 `config/agent.yaml` 中的相对路径，并确认相邻的训练项目包含 `legged_gym/scripts/train.py`。

真实训练立即失败时，查看页面日志和 `python -m rl_training_agent doctor` 的输出。OpenCLI 登录、图片上传、百炼密钥/端点、CUDA 或 Isaac Gym 异常都会在训练日志中保留。
