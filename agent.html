强化学习训练 Agent

本项目不是“让 GPT 自动调几个参数”，而是学习如何把一个不稳定的语言模型， 嵌入一个可恢复、可验证、有实验谱系的机器人训练系统。

Why It Is Different

它和一般 Agent 有什么区别

一般 Agent 的终点是答案；这个 Agent 的终点是一个经过多轮实验验证的机器人策略 checkpoint。

一般 Agent

信息与工具编排

  • 一次任务通常在秒或分钟内完成
  • 工具结果相对确定
  • 主要状态是对话上下文
  • 错误成本通常是回答不准确
  • 输出多为文字、文件或查询结果
VS
强化学习训练 Agent

长期实验决策系统

  • 任务持续数小时甚至数天
  • 训练结果存在随机性和局部最优
  • 状态是实验树、配置、指标和 checkpoint
  • 错误会浪费 GPU 预算或产生错误行为
  • 输出是策略、配置、视频与实验报告
学习目标： 不是掌握“一个万能 Agent 框架”，而是掌握工具边界、结构化输出、状态恢复、实验谱系、评估与安全控制。
Learning Through Building

通过完整流程学习 Agent

每一步既是系统模块，也是一个独立的 Agent 工程知识点。

任务规格化将自然语言转换为 TaskSpec、阶段、硬约束和验收指标。
环境检查读取真实 observation、reward、termination、训练入口和配置字段。
奖励设计通过 OpenCLI 操作 ChatGPT 网页生成 RewardPlan，并使用 Schema 校验。
安全编译把 RewardPlan 映射到配置副本，生成 diff，不覆盖原配置。
训练编排冒烟训练、候选筛选、阶段预算、早停、恢复与 checkpoint 管理。
数据采集同步保存 TensorBoard、reward 分量、trajectory 和多视角视频。
视觉评论关键事件抽帧，上传 ChatGPT 网页，输出结构化行为报告。
融合评估确定性物理指标 + 视觉语义，不让总 reward 单独决定成功。
实验决策继续、修改、回滚、重训、人工审核或完成。
可恢复执行状态落盘、失败重试、预算耗尽处理和任务恢复。
System Architecture

建议采用“确定性外壳 + LLM 推理核心”

模型负责模糊推理，程序负责精确执行与验证。OpenCLI 只是 LLM Provider，不应该控制整个系统。

1确定性执行层

环境检查、配置修改、训练进程、指标计算、事件检测、成功率、超限判断。

2LLM 推理层

任务理解、奖励候选、失败解释、视觉语义评论、下一轮实验假设。

3状态与实验层

状态机、实验谱系、配置 hash、checkpoint、提示词版本、恢复与审计。

4安全边界

禁止任意 Shell、禁止覆盖原配置、路径白名单、超时、预算和人工审批。

5视觉评论员

只在评估阶段工作：视频预处理、关键帧、纯视觉分析、训练诊断。

6Provider 抽象

生产使用 OpenCLI + Chrome ChatGPT；测试使用 Mock Provider，保证离线测试。

Roadmap

推荐的六阶段学习路线

每个阶段都有明确产出。先跑通最小闭环，再逐步增加自动化。

M0OpenCLI Provider：先学会可靠地“问网页”
目标：Python 调用 OpenCLI，绑定或打开 Chrome 中的 ChatGPT，发送文本、上传图片、等待回答、提取最新回复并解析 JSON。
Agent 知识：Provider 抽象、超时、重试、DOM 变化、结构化输出、Mock。
M1训练日志分析器：让程序先会“看数据”
目标：读取 TensorBoard 和 reward 分量，输出统一 JSON 摘要。
Agent 知识：工具输入输出、幂等性、数据契约、异常处理。
M2半自动闭环：Agent 建议，人类批准
目标：TaskSpec → RewardPlan → 配置副本 → 训练 → 诊断 → 人工确认。
Agent 知识：Human-in-the-loop、状态机、实验目录、审计。
M3视觉评论员：把“动作像不像”加入评估
目标：rollout 视频与 trajectory 同步，自动抽取事件关键帧，通过 OpenCLI 上传网页，返回结构化视觉报告。
Agent 知识：多模态输入、证据引用、不确定性、视觉与数值冲突处理。
M4候选搜索：从单链路升级为实验树
目标：每轮生成 2–3 个候选，短训练筛选，保留父子实验关系，支持回滚和重训。
Agent 知识：规划、预算、分支、选择、lineage、warm-start 风险。
M5自动闭环：可恢复、可测试、可验收
目标：任务中断可恢复，预算耗尽可停止，多 seed 验证，完成条件由确定性指标与视觉对齐共同决定。
Agent 知识：可靠性、回归测试、状态恢复、Guardrails、Observability。
Minimum Viable Agent

最适合团队起步的 MVP

先把 Agent 限制在一个机器人、一个已有任务、已有 reward，仅允许调整权重。

①

输入

任务描述、当前 reward 配置、训练摘要、物理任务指标、实验历史。

②

允许决策

仅允许 CONTINUE、REVISE_WEIGHT、STOP、HUMAN_REVIEW。

③

完成标准

dry-run 端到端通过；真实训练可启动；配置不被覆盖；决策可追溯。

建议的最小决策 Schema

{
  "decision": "REVISE_WEIGHT",
  "confidence": 0.78,
  "reason": "姿态奖励贡献偏低，侧向摆动持续存在",
  "changes": [
    {
      "reward": "orientation",
      "old_weight": -1.0,
      "new_weight": -1.25,
      "expected_effect": "减小身体横滚",
      "risk": "过强时可能抑制步态探索"
    }
  ],
  "requires_human_approval": true
}
Visual Critic

视觉评论员在系统中的正确位置

视觉评论员不是控制器，也不是唯一裁判。它负责判断动作是否符合语言语义，并定位失败阶段。

程序负责精确事实

  • 四脚是否真正离地
  • 落地时间差与足端滑动速度
  • roll / pitch、扭矩、能耗、碰撞
  • 任务成功率和多 seed 统计

视觉模型负责语义质量

  • 动作是否自然、协调
  • 阶段顺序是否符合要求
  • 是否采用错误策略完成任务
  • 是否存在明显抖动、拖地或姿态异常

推荐两阶段视觉调用

事件检测使用 trajectory 找到起跳、落地、最大侧倾等事件。
纯视觉评论只给任务和图像，不给 reward，降低锚定偏差。
训练诊断再加入 reward、PPO 和物理指标，分析原因。
融合决策视觉与数值一致才自动生成修改候选。
Data Contracts

Agent 稳定性的核心：明确数据契约

不要依赖散文式回复。关键模块之间只交换经过验证的结构化数据。

对象 生产者 消费者 关键字段 验证方式
TaskSpec ChatGPT 网页 环境检查器 / Reward Designer 阶段、required behavior、success metrics Pydantic + 环境能力检查
RewardPlan ChatGPT 网页 配置编译器 reward、weight、phase、风险、curriculum Schema + Reward Registry
TrainingReport 指标采集器 训练诊断器 raw/weighted reward、PPO、task metrics 数值范围与缺失检查
VisualReport ChatGPT 网页 融合评估器 phase score、failure mode、evidence frame 枚举 + 置信度 + 帧存在性
AgentDecision 诊断器 状态机 decision、changes、checkpoint strategy 动作白名单 + 预算与审批
Team Collaboration

适合小团队的分工方式

即使只有 2–3 个人，也建议按职责分开，避免所有逻辑集中在一个 Agent 文件里。

Agent / 平台OpenCLI Provider、状态机、实验存储、恢复、CLI、测试。
RL / 环境Reward Registry、训练入口、指标、评估 rollout、物理成功条件。
视觉 / 数据视频同步、关键事件、contact sheet、视觉 Schema 与评价集。
共同负责Prompt 版本、验收标准、安全边界、失败案例库。

每周建议节奏

  • 周初：选一个可验证的单一能力目标
  • 周中：实现模块并增加 mock / dry-run
  • 周末：用真实训练或真实 OpenCLI 做集成测试
  • 每次失败都写入 failure case，而不是只手工修一次
Boundaries

LLM 与确定性程序的边界

任务交给谁理由
从自然语言提出奖励候选LLM需要语义理解和开放式假设生成
计算 reward 均值、成功率、NaN程序结果可精确计算，不应交给模型猜测
解释动作为何不自然视觉 LLM属于模糊语义评价
判断足端是否精确打滑仿真数据需要接触与速度的数值证据
执行训练命令受限工具只能由业务接口构造，不允许模型生成任意 Shell
最终决定真实机器人部署人工涉及实机安全与不可逆风险

Final Takeaway

这个项目最值得学习的是什么

如何把一个会犯错、会漂移、输出不稳定的语言模型，放进一个 有边界、有状态、有证据、有回滚能力的软件系统中。

PPO 和 Isaac Gym 决定策略能不能学会；Agent 工程决定整个训练过程能不能被可靠地自动化。
